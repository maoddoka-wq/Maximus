CORRECTION CIBLÉE — PARAMÈTRES DU PROFIL ENTREPRISE

J'ai un problème précis dans :

Administration de l'entreprise → Profil / Paramètres → Modification des paramètres

Sur la page, les paramètres s'affichent correctement, mais lorsque j'appuie sur :

« Enregistrer les modifications »

une erreur apparaît :

"Cannot read properties of null (reading 'trim')"

Voir la capture d'écran fournie.

IMPORTANT

Ne corrige PAS simplement l'erreur en ajoutant ".trim()" avec une valeur par défaut partout.

Je veux que tu identifies exactement quelle donnée est "null", pourquoi elle arrive à "null", à quel endroit ".trim()" est appelé et pourquoi le formulaire d'enregistrement accepte cette situation.

---

Cette correction concerne uniquement le problème d'enregistrement des paramètres du profil entreprise.

Avant de modifier le code :

- identifie l'API utilisée ;

- identifie le contrôleur/service ;
- identifie le modèle ;
- identifie les colonnes DB ;
- identifie les validations ;
- identifie exactement l'endroit où ".trim()" est exécuté.

Ne refactore pas toute l'application.

Ne change pas la navigation.

Ne change pas les permissions.

Ne change pas le système de modules.

Ne change pas l'e-commerce.

Ne change pas les autres pages.

2. TROUVER LA CAUSE RACINE

Recherche dans le code toutes les utilisations de :

".trim()"

dans le flux de sauvegarde de ce formulaire.

Identifie la variable exacte qui provoque :

"Cannot read properties of null"

Par exemple, cela peut être un champ comme :

- nom ;
- description ;
- téléphone ;
- email ;
- adresse ;
- couleur ;
- logo ;
- autre paramètre.

Mais ne suppose pas lequel.

Vérifie réellement la valeur reçue.

4. CORRECTION PROPRE

Une fois la cause trouvée, corrige-la au bon niveau.

Si un champ peut réellement être vide :

→ le code doit gérer correctement "null" / chaîne vide selon les règles métier.

Si le champ est obligatoire :

→ validation claire avant l'envoi.

Si la DB retourne "null" alors que le frontend attend une chaîne :

→ corriger le mapping ou la normalisation à la bonne couche.

Si le backend accepte une valeur incorrecte :

→ corriger la validation backend.

Si le frontend construit incorrectement le payload :

→ corriger le payload.

Ne masque pas le problème avec une succession de "|| ''" ou "?.trim()" sans comprendre la cause.

Une valeur par défaut est acceptable uniquement si elle correspond réellement au comportement métier attendu.

---

5. VÉRIFIER TOUS LES CHAMPS DU FORMULAIRE

Teste l'enregistrement avec :

Cas 1

Tous les champs remplis.

Cas 2

Un champ optionnel vide.

Cas 3

Plusieurs champs optionnels vides.

Cas 4

Champs contenant des espaces.

Cas 5

Valeurs normales.

Cas 6

Modification d'une seule valeur.

Cas 7

Aucune modification.

Dans chaque cas :

- aucune erreur JavaScript ;
- aucune erreur "trim" ;
- API correcte ;
- sauvegarde réelle ;
- données correctement enregistrées.

---

6. VÉRIFIER LA PERSISTANCE

Après avoir enregistré :

1. vérifier que l'API répond correctement ;
2. vérifier que la DB contient les nouvelles valeurs ;
3. actualiser complètement la page ;

5. se déconnecter ;
6. se reconnecter ;
7. vérifier à nouveau.

Le bouton « Enregistrer les modifications » ne doit afficher un succès que si la sauvegarde backend a réellement réussi.
