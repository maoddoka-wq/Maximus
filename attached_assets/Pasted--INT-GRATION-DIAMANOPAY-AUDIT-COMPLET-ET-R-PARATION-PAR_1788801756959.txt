4. RÉPONSE DE DIAMANOPAY

CRITIQUE :

Après création du paiement, ne considère pas simplement HTTP 200 comme « paiement réussi ».

Analyse la réponse réelle de DiamanoPay.

Récupère notamment le statut et le checkout/payment URL retourné.

Si DiamanoPay renvoie par exemple :

status = pending
checkout_url = ...

MAXIMUS doit correctement récupérer checkout_url et rediriger le client vers cette URL.

Le frontend ne doit pas attendre indéfiniment.

Si l'API échoue :

- afficher une erreur claire ;
- enregistrer l'erreur côté backend ;
- conserver la réponse HTTP et le code d'erreur ;
- afficher au client une information compréhensible.

NE JAMAIS afficher simplement :
« Une erreur est survenue ».

Je veux connaître la vraie cause dans les logs serveur.

6. WEBHOOK

Implémente ou corrige le webhook DiamanoPay selon la documentation officielle.

Le webhook doit être une vraie route backend publique HTTPS.

Exemple d'architecture :

POST
https://maximus-erp.onrender.com/api/payments/diamanopay/webhook

ATTENTION :
N'utilise cette URL exacte que si cette route existe réellement dans le code.

Vérifie la route réellement enregistrée par Laravel/Node.

Le webhook doit :

- accepter la requête DiamanoPay ;
- vérifier correctement son authenticité selon la documentation ;
- récupérer l'identifiant de transaction ;
- retrouver la transaction MAXIMUS ;
- vérifier la transaction auprès de DiamanoPay si nécessaire ;
- mettre à jour le statut ;
- être idempotent ;
- ne jamais créer deux fois le même paiement ;
- enregistrer les événements reçus.
