4. AUDIT DE L'APPLICATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Effectue une inspection complète mais NON DESTRUCTIVE.

Cherche notamment :

A. AUTHENTIFICATION

- login
- logout
- sessions
- cookies
- expiration
- fixation de session
- récupération de mot de passe
- changement de mot de passe
- protection des comptes sensibles.

B. AUTORISATION
Vérifie particulièrement :

- Policies
- middleware
- permissions
- rôles
- modules
- sous-fonctionnalités
- actions
- company scope
- unit scope.

Respecte la chaîne obligatoire définie dans replit.md :

module existe / non supprimé
→ company allowedModules
→ unit moduleIds
→ rôle appartenant à la même company/unit/ancestor
→ rôle possède "voir"
→ sous-feature possède "voir"
→ action possède sa propre permission.

Le scope le plus restrictif doit toujours s'appliquer.

C. MULTI-TENANT / IDOR / BOLA

Cherche les possibilités permettant à un utilisateur d'accéder aux données d'une autre entreprise en modifiant :

- ID
- companyId
- unitId
- roleId
- resourceId
- slug
- URL
- paramètres HTTP
- payload JSON.

IMPORTANT :

Tu peux analyser le code et effectuer des tests non destructifs.

Tu ne dois PAS modifier les données pour démontrer une vulnérabilité.

D. SEC-001 — COMPANY PASSWORD

Vérifie spécifiquement la route de changement du mot de passe company/admin précédemment identifiée.

Détermine :

- qui peut appeler la route
- quel middleware protège la route
- quelle Policy intervient
- quel rôle peut modifier quel compte
- si un utilisateur standard peut cibler un compte administrateur
- si une réauthentification est nécessaire.

Ne change aucun mot de passe réel.

Si nécessaire, reproduis le problème uniquement avec des comptes de test/localement.

E. ENDPOINTS PUBLICS

Inspecte notamment :

- /api/healthz
- /api/installation
- autres routes publiques.

Détermine si elles exposent inutilement :

- version
- environnement
- état PostgreSQL
- informations d'installation
- configuration interne
- données sensibles.

Ne désactive aucune route pendant l'audit.

F. FINANCES / DIAMANOPAY

Inspecte :

- paiements
- webhooks
- transactions
- idempotence
- vérification des signatures
- montant
- devise
- statut
- association utilisateur/entreprise.

Ne déclenche AUCUN paiement réel.

Ne rejoue aucun webhook réel contre la production.

G. E-COMMERCE

Vérifie :

- panier
- commandes
- produits
- prix
- stock
- paiement
- isolation multi-tenant
- manipulation des IDs
- double soumission.

H. UPLOADS

Inspecte :

- validation MIME
- extension
- taille
- nom de fichier
- stockage
- accès aux fichiers
- fichiers exécutables
- path traversal.

Ne téléverse aucun fichier dangereux en production.

I. INJECTION / XSS

Inspecte :

- SQL injection
- XSS
- commandes système
- template injection
- HTML non échappé.

Utilise uniquement des tests inoffensifs et non persistants.

J. CSRF / CORS

Vérifie :

- configuration CORS
- cookies
- credentials
- CSRF
- origines autorisées.

K. SECRETS

Recherche :

- API keys
- tokens
- passwords
- secrets
- clés privées
- credentials
- secrets dans frontend
- secrets dans Git.

IMPORTANT :

Ne révèle pas les valeurs secrètes dans le rapport.

Si tu trouves un secret :

→ indique seulement son emplacement et son type
→ masque sa valeur.

Exemple :

SECRET DÉTECTÉ :
fichier : xxx
type : API key
valeur : [MASQUÉE]

- vulnérabilités connues.

Ne mets aucune dépendance à jour automatiquement.
